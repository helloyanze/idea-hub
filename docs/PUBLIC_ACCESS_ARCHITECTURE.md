# Idea Hub 公网访问：架构决策与完整流程说明

> 版本：v1.0（2026-08-11）
> 适用：单用户自托管 Web 应用的公网访问方案（国内云服务器 + 国内网络环境）
> 访问地址：https://idea.example.com

---

## 一、速查：怎么登录

| 项目 | 值 |
|---|---|
| 访问地址 | https://idea.example.com（国内直连不稳，建议开梯子） |
| 用户名 | idea |
| 密码 | 见服务器 `$HOME/idea-hub/.env`（部署时生成，已交付一次） |
| 登录方式 | 浏览器原生弹窗（HTTP Basic Auth），输入一次后浏览器记住 |
| 本地备用通道 | SSH 隧道：`ssh -N -L 8000:127.0.0.1:8000 <user>@<server-ip>` → http://127.0.0.1:8000（同样需要登录凭证） |

---

## 二、架构总览（现在是怎么跑的）

```
你的浏览器（开梯子）
    │  https://idea.example.com（HTTPS，TLS 由 CF 终结）
    ▼
Cloudflare 边缘（DNS 解析 + 自动证书 + DDoS/基础防护）
    │  加密隧道（QUIC/HTTP2，cloudflared 主动出站建立）
    ▼
你的服务器 <server-ip>（公网仅开 SSH 22，8000 只监听 127.0.0.1）
    │  cloudflared 进程（常驻，开机自启）
    ▼
Idea Hub（FastAPI + Basic Auth 中间件，验证用户名密码）
```

**流量路径**：浏览器 → CF 边缘 → 隧道 → 服务器本地 8000 → 认证通过 → 页面。

**关键事实**：
- 服务器没有向公网开放任何 Web 端口（8000 仅本机可访问）
- HTTPS 证书由 Cloudflare 自动签发管理，无需自管
- 认证由应用层 Basic Auth 完成（因为 Cloudflare Access 需要信用卡，未启用，见第四节）
- 密码传输安全：Basic Auth 的凭证包在 HTTPS 里，不会明文暴露

## 三、为什么这样做（决策链）

### 3.1 原始需求
1. 公网也能打开 Idea Hub 界面（不仅限 SSH 隧道）
2. 只有我一个人用，要加用户验证
3. 国内网络环境（服务器在腾讯云，本人在国内）

### 3.2 约束条件
- 国内访问 Cloudflare 免费版直连不稳 → 访问需开梯子（用户接受）
- 无信用卡 → Cloudflare Zero Trust（Access 认证）不可用
- 国内服务器公网 80/443 需 ICP 备案，无备案域名不能走标准 HTTP 端口
- 单用户、低流量、个人项目 → 方案必须免费、低运维

### 3.3 方案对比

| 方案 | 端口暴露 | HTTPS | 认证 | 免费 | 国内可用 | 结论 |
|---|---|---|---|---|---|---|
| **A. Cloudflare 经典隧道 + Basic Auth（当前）** | 零暴露 | 自动 | 应用层密码 | ✅ | 开梯子 ✅ | **采用** |
| B. Tailscale 设备 VPN | 零暴露 | 应用层 | 设备级认证 | ✅ | ✅ 最优 | 备选（需装客户端，弃用） |
| C. Caddy/Nginx 反代 + 密码 | 暴露 443 | 自管证书 | 密码 | ✅ | ✅ 需备案/自签 | 未采用 |
| D. Cloudflare Zero Trust（Access） | 零暴露 | 自动 | CF 托管认证 | ❌ 要信用卡 | 开梯子 | 未采用 |
| E. 裸开 8000 端口 + 应用登录 | 暴露 | 无 | 明文风险 | ✅ | ✅ | 否决（不安全） |

### 3.4 为什么选 A（当前方案）

1. **安全上限最高**：零端口暴露。攻击者扫不到服务，无从下手——比"开放端口 + 强密码"的模型安全一个量级。
2. **免备案**：流量经 CF 域名代理进入，不占用国内服务器公网 80/443，绕开 ICP 备案限制。
3. **零证书运维**：HTTPS 全自动，无过期/续期烦恼。
4. **免费**：域名解析、隧道、证书、基础防护全部免费。
5. **成本可控**：唯一代价是访问需开梯子（CF 国内直连不稳），对"确保访问"的需求可接受。

## 四、中间没有采用的其他流程（及原因）

### 4.1 为什么没用 Cloudflare Zero Trust（Access 认证）
- **卡点**：创建 Zero Trust 组织要求绑定信用卡（免费计划也要验证），用户无信用卡。
- **它的好处**（如果可用）：认证托管在 CF 边缘（邮箱验证码/一次性 PIN），服务器零代码改动、有内置防暴力破解。
- **替代**：认证下沉到应用层 Basic Auth。单用户场景安全性等价（密码 + HTTPS + 浏览器记住），代价是密码明文存在于服务器 .env（已 chmod 600）与浏览器记住凭据。

### 4.2 为什么没用 Tailscale
- **它是什么**：设备级私有网络（WireGuard），服务器 + 用户设备装客户端后，通过虚拟内网 IP 访问，完全无公网暴露，无需任何域名。
- **没选的原因**：需要用户在电脑/手机上安装 Tailscale 客户端并登录（多一步设备管理）；用户已有域名且倾向"浏览器直接打开"的访问形态。
- **它的优势仍在**：如果将来想要"不开梯子也能访问"或"更多设备接入"，Tailscale 是国内网络下最顺滑的补充方案（保留为备选）。

### 4.3 为什么没用 Caddy / Nginx 反向代理
- **它是什么**：服务器直接监听 443，配 Let's Encrypt 证书 + 密码认证，域名 A 记录指向服务器 IP。
- **没选的原因**：
  - 国内服务器公网 80/443 需 ICP 备案（无备案会被云厂商拦截）；
  - 即使走非标端口 + 自签证书，浏览器会有安全警告，体验差；
  - 服务器端口暴露，安全模型弱于隧道。
- **适用场景**：有备案域名、希望国内直连（无需梯子）时可以考虑。

### 4.4 为什么没用裸端口 + 应用内登录（最简单但否决）
- 直接 `uvicorn --host 0.0.0.0` + 登录页。
- **否决原因**：无 HTTPS 时密码明文传输；端口可被全网扫描和暴力破解；无 DDoS 缓冲。单用户安全底线不满足。

### 4.5 为什么没用 frp / 花生壳等内网穿透
- 国内穿透服务多面向"无公网 IP 的内网机器"（本场景服务器本身有公网 IP，不需要）；免费档速度/稳定性无保障，且同样没有边缘认证能力。

### 4.6 SSH 隧道的定位（原来的方案，现在是备用）
- 之前全靠 `ssh -N -L 8000:...` 隧道访问。
- 现在作为**应急备用通道**保留：CF 故障或梯子不可用时，本地隧道仍可访问（同样要输密码）。

## 五、安全边界与运维

### 5.1 安全清单（已落实）
- [x] 服务器公网仅开放 SSH 22；8000 端口只监听 127.0.0.1
- [x] SSH 密钥认证（无密码登录）
- [x] Basic Auth（用户名/密码，HTTPS 加密传输，hmac.compare_digest 防时序攻击）
- [x] 认证凭证存储：`$HOME/idea-hub/.env`，权限 600
- [x] cloudflared 凭据文件权限 600
- [x] 开机自启：mihomo、uvicorn（加载 .env）、cloudflared（crontab @reboot）
- [ ] Cloudflare 面板建议开启：免费 WAF 托管规则集（可选）

### 5.2 日常运维
| 操作 | 方法 |
|---|---|
| 改登录密码 | 服务器改 `.env` 的 IDEAHUB_AUTH_PASS → 重启 uvicorn |
| 查看隧道状态 | `cloudflared tunnel info idea-hub` 或看 `~/.cloudflared/tunnel.log` |
| 重启 Web | 杀 uvicorn 进程 → `cd $HOME/idea-hub && bash -c 'set -a; source .env; set +a; nohup .venv/bin/uvicorn idea_hub.server:app --host 127.0.0.1 --port 8000 > logs/server.log 2>&1 &'` |
| 禁用公网访问 | 停 cloudflared：`pkill -f cloudflared`，删 crontab 对应行 |
| 恢复 SSH 隧道访问 | `ssh -N -L 8000:127.0.0.1:8000 <user>@<server-ip>` |

### 5.3 故障排查
| 现象 | 排查 |
|---|---|
| 访问超时 | 梯子是否开启；CF 面板域名状态 Active；`curl https://idea.example.com` 服务器侧看隧道 |
| 401 弹窗循环 | 凭证错误；改过 .env 未重启 uvicorn |
| 502/530 | cloudflared 挂了（看 tunnel.log）；Idea Hub 服务挂了（看 logs/server.log） |
| 本地可开、公网打不开 | 隧道断 → 重启 cloudflared；DNS 未生效 → CF 面板检查 |

## 六、架构图（完整视图）

```
                     ┌────────────── 你的使用路径 ──────────────┐
  浏览器（电脑/手机）                                            │
   │  https://idea.example.com（开梯子）                     │
   ▼                                                            │
Cloudflare 边缘                                                │
   │  DNS：idea.example.com → CNAME → tunnel                │
   │  TLS：自动证书（边缘终止）                                  │
   │  防护：DDoS 基础 + WAF（可选）                              │
   ▼  加密隧道（cloudflared 出站，端口 7844/443）                 │
服务器 <server-ip>                                          │
   ├─ cloudflared（常驻，crontab @reboot）                      │
   ├─ uvicorn :8000（仅 127.0.0.1，加载 .env 认证变量）          │
   │    └─ Basic Auth 中间件（idea / 密码）                      │
   ├─ mihomo 代理（出站下载/API 用，与公网访问无关）               │
   └─ SSH :22（密钥认证，本地隧道备用通道）                       │
                                                                  │
  备用：ssh -N -L 8000:127.0.0.1:8000 → http://127.0.0.1:8000 ───┘
```
