# Idea Hub 设计规格

> 日期：2026-08-11
> 状态：已批准
> 目标模式：自媒体内容类（暂定，可切换）

## 背景与目标

每日自动收集网络热点，由 AI 生成相关 idea（含初步构思与可行性评分）。
可行性低于 6 分（满分 10）的 idea 自动留档；达到或超过 6 分的进入用户待办，
由用户决定是否推进。用户挑选的任务进入等待队列，由 AI 自动执行并产出内容。

## 架构总览

```
┌─────────────────────────────────────────────────────────────┐
│                    本地 Web 应用 (FastAPI)                     │
│  REST API (端口 8000)  +  单页前端 (HTML/JS/SortableJS)        │
│                    ┌──────────────┐                           │
│                    │   SQLite     │  ← 唯一数据源，所有组件读写这里
│                    │  idea.db     │                           │
│                    └──────────────┘                           │
└─────────────────────────────────────────────────────────────┘
         ▲                          ▲
         │                          │
┌────────┴─────────┐    ┌───────────┴──────────┐
│ Python CLI 工具   │    │  Hermes 定时任务       │
│ (collect.py      │    │  (cron 驱动, LLM 智能) │
│  generate.py     │    │  - 每日收集+生成 idea   │
│  execute.py)     │    │  - 周期执行等待队列     │
└──────────────────┘    └───────────────────────┘
         │                          │
         └──────────┬───────────────┘
                    ▼
       ┌────────────────────────┐
       │  产出目录 outputs/       │
       │  按任务组织的 .md 文件    │
       └────────────────────────┘
```

组件职责：

1. **SQLite（idea.db）**：唯一数据源。任务、队列状态、热点记录、目标模式、
   来源配置全部存于此。多组件通过数据库协作，无直接耦合。
2. **Web 应用**：只负责展示与交互——队列视图、拖拽移动、详情查看、手动修改
   （含分数）、手动触发执行。不包含任何 AI 逻辑。
3. **Python CLI**：数据操作入口（查任务、改状态、写产出），供 Hermes agent
   与 Web 后端复用。
4. **Hermes 定时任务**：两个 cron——每日收集热点并生成 idea 入列；周期检查
   等待队列并执行任务。
5. **产出目录（outputs/）**：按 `tasks/<task_id>/` 组织 markdown 正文，
   任务记录只存摘要与相对路径。

关键决策：AI 能力全部由 Hermes agent 承载（cron 与手动触发），Web 应用零
AI 逻辑。职责清晰，且 AI 部分完全复用 Hermes 的技能与模型配置。

## 数据模型

### targets（目标模式表）

| 字段 | 说明 |
|---|---|
| id | 主键 |
| name | 目标名（如"自媒体内容"） |
| description | 目标描述，指导 AI 生成 idea |
| score_dimensions | JSON：评分维度与权重（不同目标可不同） |
| is_active | 当前激活的目标（同一时间仅一个） |

### sources（来源配置表）

| 字段 | 说明 |
|---|---|
| id | 主键 |
| type | `hotlist` 或 `rss` |
| name | 来源名（如"微博热搜"） |
| url | 热榜 API 或 RSS 地址 |
| enabled | 是否启用 |

### hot_items（热点记录表）

| 字段 | 说明 |
|---|---|
| id | 主键 |
| source_id | 外键 → sources |
| title / url | 热点标题与链接 |
| content_snapshot | 内容摘要快照 |
| collected_at | 收集时间 |

唯一约束：(source_id, url)，防止重复收集。

### tasks（任务表，即 idea）

| 字段 | 说明 |
|---|---|
| id | 主键 |
| title / description | idea 标题与初步构思 |
| hot_item_id | 外键，关联来源热点（可空） |
| target_id | 外键 → targets |
| status | `archived` / `todo` / `waiting` / `in_progress` / `done` |
| feasibility_score | 综合分 1-10 |
| score_breakdown | JSON：各维度分数 + AI 解释 |
| ai_summary / output_path | 执行后的摘要与产出文件路径 |
| notes | 用户备注 |
| created_at / updated_at / completed_at | 时间戳 |

设计要点：

- 五队列不是独立表，而是 tasks 的 status 字段。拖拽移动即一次状态更新。
- 评分维度挂在目标模式上，不同目标使用不同评分维度。
- 跨来源重复热点不做自动合并；由 Hermes 生成 idea 时识别相似 idea 并跳过。

### settings（全局设置表）

key-value 结构：评分阈值（默认 6）、收集时间、自动执行频率、产出目录路径等。

## 核心流程

### 流程 A：每日收集与生成（Hermes cron 每日定时）

```
触发 → collect.py 抓取所有启用来源（热榜 API + RSS，写入 hot_items 去重）
    → Hermes agent 按当前激活目标的维度，判断每条热点是否值得生成 idea
      （过滤低价值与重复主题）
    → 生成 idea：标题 + 初步构思 + 分维度评分(1-10) + 解释
    → 写入 tasks，按规则入列：
        score >= 6  → status = todo（待办）
        score <  6  → status = archived（留档）
    → 通过 Web 界面查看当日收集结果
```

### 流程 B：任务执行（两种触发）

```
用户手动触发（界面"执行"按钮） 或  Hermes cron 周期检查
        ↓
等待队列(status=waiting)中选任务 → status = in_progress
        ↓
Hermes agent 按任务目标执行创作（如生成文章正文）
        ↓
正文写入 outputs/tasks/<task_id>/ 目录
任务记录更新：ai_summary、output_path
        ↓
status = done（已完成）
```

### 流程 C：用户操作

| 操作 | 实现方式 |
|---|---|
| 待办/留档 → 等待队列 | 界面拖拽或"加入等待"按钮 |
| 查看详情 | 点击任务打开详情面板（全部字段 + 评分明细 + 产出链接） |
| 修改任务 | 编辑标题/构思/分数/备注，保存即更新 |
| 已完成 → 进行中/待办 | 拖拽回移，附用户修改意见（notes），AI 按意见继续加工 |

关键决策：

- 生成与执行都调用 Hermes agent（cron 的 LLM 能力），CLI 只做数据读写。
- 手动触发执行是"一次性 cron 运行"：点击按钮 → 调起后台 Hermes 任务 →
  完成后状态自动更新。
- 所有移动都是 status 字段更新 + updated_at，无复杂事务。

## 前端界面

单页三栏式看板布局：

```
┌─────────────────────────────────────────────────────────────┐
│ 顶部栏：应用名 | 目标模式切换(下拉) | 来源管理 | 设置 | 立即收集 │
├──────────┬──────────┬──────────┬──────────┬─────────────────┤
│  留档    │  待办    │  等待    │ 进行中   │  已完成          │
│ (<6分)   │ (>=6分)  │ (已挑选) │ (执行中) │ (产出完成)       │
│ 卡片列表  │ 卡片列表  │ 卡片列表  │ 卡片列表  │ 卡片列表        │
├──────────┴──────────┴──────────┴──────────┴─────────────────┤
│ 状态统计：各队列数量 | 今日新增 | 执行中任务实时状态            │
└─────────────────────────────────────────────────────────────┘
```

卡片内容：标题 + 可行性分数徽标（颜色区分：红 <6 / 黄 6-7 / 绿 >=8）+
来源热点摘要。

交互明细：

| 交互 | 实现 |
|---|---|
| 跨队列移动 | SortableJS 拖拽（含已完成→进行中/待办的反向拖回） |
| 查看详情 | 点击卡片 → 右侧滑出详情面板：构思全文、评分明细、关联热点、产出链接、时间线 |
| 修改 | 详情面板内联编辑：标题、构思、分数（滑块）、备注 |
| 手动执行 | 等待/进行中队列顶部"执行"按钮 → 调起后台 Hermes 任务 |
| 目标切换 | 顶部下拉切换 → 界面按 target 过滤显示 |
| 来源管理 | 弹窗：增删启停来源，测试连通性 |

前端技术：单个 `index.html` + 原生 JS + 少量 CSS。SortableJS 本地文件引入
（不依赖 CDN，离线可用）。无构建步骤，FastAPI 直接托管静态文件。

## 错误处理

| 场景 | 策略 |
|---|---|
| 某来源抓取失败（API 变更/网络） | 跳过该来源并记日志，不影响其他来源；界面显示最近失败状态 |
| AI 生成 idea 失败 | 自动重试 1 次；仍失败则记录错误，当日该热点跳过 |
| 任务执行失败 | 任务回到等待队列并标记失败原因；可手动重新触发 |
| cron 与手动触发并发执行同一任务 | 状态机守护：仅 `waiting` 可转 `in_progress`（原子 UPDATE 条件判断） |
| 数据库损坏 | SQLite WAL 模式；每日收集前自动备份 idea.db（保留最近 7 份） |
| 产出文件写入冲突 | 按 task_id 隔离目录，文件名带时间戳 |

## 测试策略

- CLI 单元测试（pytest）：状态转换规则、评分阈值入列逻辑（>=6 待办 / <6
  留档）、去重。
- API 测试：任务 CRUD、状态更新、来源管理接口。
- 流程测试：模拟"收集 → 入列 → 执行 → 完成"全链路（用假数据源）。
- 前端无构建步骤，核心逻辑（拖拽、过滤）集中在少量 JS，人工走查。

## 明确不做（YAGNI）

- 用户认证与多用户
- 云部署
- 消息通知
- 历史趋势图表
- 撤销操作
