# Idea Hub 界面设计文档

> 版本：v1.0（2026-08-11）
> 用途：供 UI/UX 设计师在设计软件（Figma 等）中完成 Idea Hub 界面设计的完整参考。
> 配套：功能规格见 `docs/superpowers/specs/2026-08-11-idea-queue-design.md`（本文件聚焦设计与体验，两者冲突时以本文件为准的视觉部分）。

---

## 1. 产品概述

### 1.1 一句话定位

**Idea Hub 是一个把"每日热点信息过载"转化为"可执行创作任务队列"的个人内容创作管理系统。**

### 1.2 核心价值主张

| 用户痛点 | Idea Hub 的解法 |
|---|---|
| 每天刷大量热点，但不知道哪些值得写 | 自动收集多源热点 + AI 严格筛选（宁缺毋滥） |
| 有了想法不知如何落地 | AI 生成带完整构思（角度/读者/结构）的 idea |
| 想法散落在各处，没有管理 | 五队列看板统一管理，拖拽即调度 |
| 待办堆积无从下手 | 评分分级（红黄绿）+ 待办配额（默认 10 条）+ 标签过滤 |
| 内容产出需要执行 | 一键加入执行队列，AI 自动产文并落盘 |

### 1.3 产品形态

- **私有部署的 Web 应用**（单用户，无登录认证），部署在个人云服务器，通过 SSH 隧道访问
- 前端为原生 HTML/JS/CSS 单页应用，无构建步骤
- 数据源：百度热搜（热榜 API）、GitHub Trending、HackerNews、RSS（均可配置启停）

### 1.4 核心使用场景（用户故事）

1. **每日早晨**：打开看板，浏览"待办"列的高分 idea（绿色 8 分优先），挑选今天要做的 1-2 个拖入"等待"
2. **快速决策**：扫一眼卡片（标题 + 分数徽标 + 标签 + 摘要），决定留下/删除/执行
3. **深入查看**：点击卡片打开抽屉，看 AI 构思全文、评分明细、关联热点，可修改标题/摘要/分数/备注
4. **触发执行**：点"执行"，任务进入执行队列，当晚 AI 自动产出文章
5. **维护系统**：管理来源（启停、关键词过滤）、管理标签、调整待办配额、暂停/恢复每晚自动运行

## 2. 目标用户

### 2.1 用户画像

- **单用户**：产品无多用户概念，界面不需要账号体系、权限、协作
- **身份**：个人内容创作者 / 独立开发者，关注科技、AI、互联网行业
- **设备**：桌面浏览器为主（Windows + Chrome/Edge），可能有平板
- **使用频率**：每日 1-2 次，每次 5-15 分钟（碎片化、快进快出）
- **技术水平**：熟悉 Web 操作，但不是设计师；期望"打开就知道怎么用"

### 2.2 用户心智模型

用户把系统理解为三件事：

1. **"今天有什么值得做"** —— 待办列（精选区）
2. **"这个 idea 怎么样"** —— 卡片与抽屉（信息区）
3. **"让 AI 去干活"** —— 执行（自动化区）

设计应让这三个心智区域在首屏自然呈现，无需学习。

## 3. 功能需求（对设计的约束）

### 3.1 核心对象与属性

**任务（Task / Idea）**——界面第一对象：

| 属性 | 说明 | 展示要求 |
|---|---|---|
| 标题 | AI 生成的中文标题 | 卡片主文本，2 行内 |
| 分数 | 1-10 可行性评分 | 徽标，红(<6)/黄(6-7)/绿(>=8) |
| 标签 | 0-3 个主题标签（自定义） | 小徽标，可过滤 |
| 摘要 | 一句话摘要 | 卡片副文本，1-2 行 |
| 状态 | archived/todo/waiting/in_progress/done | 由所在列体现 |
| 构思全文 | idea.md 内容 | 抽屉内展示 |
| 评分明细 | 各维度分数 JSON | 抽屉内格式化展示 |
| 产出 | output.md 链接 | 抽屉内链接 |

**五队列（列）语义**：

| 列 | 语义 | 用户行为 |
|---|---|---|
| 留档（archived） | 低分/未采用 idea 的仓库 | 浏览、可手动拖入待办 |
| 待办（todo） | 精选待选区（配额 10，高分优先） | 每日主要浏览区 |
| 等待（waiting） | 已决定要做的任务 | 拖入后等待执行 |
| 进行中（in_progress） | 正在执行（AI 或手动） | 一般只读 |
| 已完成（done） | 有产出物 | 回看、链接产出 |

### 3.2 关键操作清单

| 操作 | 位置 | 交互 |
|---|---|---|
| 查看详情 | 卡片点击 | 右侧抽屉滑入 |
| 跨列移动 | 卡片拖拽 | SortableJS 拖拽（带落点反馈） |
| 编辑标题/摘要/分数/备注 | 抽屉内 | 内联表单 + 保存 |
| 执行任务 | 抽屉内按钮 | 确认后写入执行队列 |
| 删除任务 | 抽屉内按钮（红色） | 二次确认 |
| 标签过滤 | 顶栏下拉 | 单选过滤全部列 |
| 目标切换 | 顶栏下拉 | 切换目标模式 |
| 来源管理 | 顶栏按钮 → 弹窗 | 增删启停、关键词配置 |
| 标签管理 | 顶栏按钮 → 弹窗 | 增删启停 |
| 自动运行 | 顶栏开关 | 控制每晚 cron |
| 立即收集 | 顶栏按钮 | （当前为提示，待接入） |

## 4. 信息架构

### 4.1 页面结构（单页）

```
┌────────────────────────────────────────────────────────────┐
│ 顶栏：Logo | 目标切换 | 标签过滤 | 来源管理 | 标签管理 |     │
│       立即收集 | 自动运行开关 | 统计摘要                        │
├────────────────────────────────────────────────────────────┤
│ 看板（五列横向滚动）：                                        │
│  留档 | 待办 | 等待 | 进行中 | 已完成                          │
│  ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐                   │
│  │卡片  │ │卡片  │ │卡片  │ │卡片  │ │卡片  │                   │
│  │卡片  │ │卡片  │ │      │ │      │ │卡片  │                   │
│  └─────┘ └─────┘ └─────┘ └─────┘ └─────┘                   │
├────────────────────────────────────────────────────────────┤
│ 抽屉（右侧滑出，覆盖看板右侧）：详情/编辑/执行/删除            │
└────────────────────────────────────────────────────────────┘
```

### 4.2 弹窗层级

- 来源管理弹窗（模态，遮罩 + 居中卡片）
- 标签管理弹窗（模态）
- 抽屉（非模态侧滑，可与其他弹窗共存？——建议抽屉为唯一二级层，弹窗在抽屉之上）

### 4.3 导航原则

- **单页无路由**：所有功能在首屏可达（看板 + 顶栏 + 抽屉 + 弹窗）
- 顶栏操作 ≤ 6 个（当前 5 个按钮 + 1 开关 + 2 下拉，已接近上限，设计时考虑分组）

## 5. 界面结构与组件设计

### 5.1 顶栏（Header）

**现状问题**：按钮平铺无分组、无图标、统计是纯文本串。

**设计要求**：
- 左侧：产品名（可含小图标）
- 中间/右侧分组：
  - 视图组：目标切换、标签过滤（下拉）
  - 管理组：来源管理、标签管理（按钮，可带图标）
  - 操作组：立即收集、自动运行开关（开关用 Switch 而非 checkbox）
- 统计摘要：改为徽章式（如 `待办 23` `留档 6`），点击可跳转对应列
- 响应式：窄屏时管理组折叠为"更多"菜单

### 5.2 看板（五列）

**现状问题**：五列等宽横排，卡片堆叠，无列头计数，无空状态。

**设计要求**：
- 五列横向排列，整体可横向滚动（或按需自适应）
- 列头：列名 + 数量徽章（如 `待办 23`），可点击列头快速滚动
- 列内卡片流：垂直堆叠，间距 8-12px
- 空状态：列内显示轻量提示（如"暂无任务"、"配额已满自动留档"）
- 待办列可视觉强调（如顶部渐变条，提示"精选区"）
- 拖拽：卡片拖起时半透明 + 阴影；落点列高亮边框

### 5.3 任务卡片

**现状问题**：信息密度低，分数徽标与标签混排，摘要截断无提示。

**设计要求**（卡片信息优先级从高到低）：
```
┌───────────────────────────┐
│ 标题（最多 2 行，加粗）      │ ← 第一眼
│ [8分] [AI] [Agent]         │ ← 第二眼：分数 + 标签
│ 摘要（1-2 行，次要色）       │ ← 第三眼
└───────────────────────────┘
```
- 卡片尺寸：宽 260-300px，高度自适应（标题 2 行 + 徽标行 + 摘要 2 行）
- 分数徽标：圆形或圆角方形，红/黄/绿三色，数字居中
- 标签徽标：浅色底 + 深色字（如蓝底白字），可点击直接触发过滤
- 悬停：轻微上浮 + 阴影 + 卡片右侧露出快捷操作（执行/删除）
- 完成态卡片：降低饱和度或加"已完成"标记

### 5.4 详情抽屉（Drawer）

**现状问题**：表单直排，无分区标题，评分明细是裸 pre 代码块。

**设计要求**（自上而下分区）：
1. **头部**：标题（可编辑）、分数滑块（1-10，实时显示）、关闭按钮（右上 X）
2. **标签区**：当前标签徽标 + "添加标签"（下拉选择已有标签）
3. **摘要区**：idea_summary 编辑框
4. **构思全文区**：idea_full，markdown 渲染（或等宽字体排版），可折叠
5. **评分明细区**：维度分数可视化（进度条或雷达图），替代裸 JSON
6. **关联区**：关联热点链接、产出文件链接（可下载/新窗口）
7. **备注区**：可编辑
8. **操作栏**（底部固定）：保存修改 | 执行 | 删除（红色，带确认）

### 5.5 来源管理弹窗

**现状问题**：纯表单列表，无状态可视化。

**设计要求**：
- 列表每行：名称 + 类型徽标（hotlist/rss/github-trending/hackernews）+ 启用状态开关 + 关键词摘要 + 操作（编辑/删除）
- 添加表单：类型下拉、名称、URL、条目路径、标题字段、关键词（可折叠高级配置）
- 类型徽标建议配色：hotlist=橙、rss=绿、github-trending=黑/紫、hackernews=橙红
- 每个来源显示最近收集条数/状态（可选）

### 5.6 标签管理弹窗

- 列表：标签名 + 描述 + 启用开关 + 删除
- 添加：名称 + 描述
- 显示每个标签当前关联任务数（可选）

### 5.7 统计与数据可视化（建议新增）

在顶栏下方或独立区域（可折叠）：
- **评分分布**：五队列任务数迷你条形图
- **每日新增趋势**：近 7 天新增 idea 数量
- **标签分布**：标签云或条形图（点击过滤）
- 这些可增强"今天有什么值得做"的决策效率

## 6. 交互设计规范

### 6.1 状态反馈

| 状态 | 规范 |
|---|---|
| 加载 | 骨架屏（卡片占位灰块）优于 spinner；首屏 500ms 内 |
| 空状态 | 每个列/弹窗有专属空状态文案 + 引导操作 |
| 成功 | 轻提示（toast）3 秒，不打断操作 |
| 失败 | toast + 错误详情可展开 |
| 拖拽中 | 卡片浮起（scale 1.02 + shadow-lg），落点列边框高亮 |
| 删除 | 二次确认（原生 confirm 或自定义确认弹窗） |

### 6.2 动效（克制原则）

- 抽屉滑入：200-250ms ease-out
- 弹窗淡入 + 轻微缩放：150ms
- 卡片悬停上浮：150ms
- 禁止页面级炫技动效（工具属性，效率优先）

### 6.3 键盘与快捷操作（建议）

- `Esc`：关闭抽屉/弹窗
- `1-5`：跳转五列（或 Ctrl+1-5）
- `/`：聚焦搜索框（建议新增全局搜索：标题/标签/摘要）

### 6.4 边界情况

- 分数为 null/undefined：显示"--"，不渲染红黄绿
- 构思文件缺失：抽屉显示"暂无构思文件"占位，不报错
- 超长标题：2 行截断 + 省略号，悬停显示完整
- 标签未匹配：过滤结果为空时显示"该标签下暂无任务"

## 7. 视觉风格建议

### 7.1 设计基调

- **定位**：效率工具（类 Linear / Things / Trello 的克制感），非消费级娱乐产品
- **关键词**：清晰、克制、信息密度适中、深夜友好（开发者用户常在夜间使用）

### 7.2 主题

- **默认浅色**：背景 #f9fafb，卡片 #ffffff，主文字 #111827，次要 #6b7280
- **深色模式**（建议 v2 支持）：背景 #111827，卡片 #1f2937，文字 #f9fafb
- 强调色建议：蓝 #2563eb（交互/选中），绿 #16a34a（高分/成功），黄 #d97706（中分/警示），红 #dc2626（低分/删除）

### 7.3 分数色阶（与业务强绑定，勿改语义）

- 红色 `<6`：不可行/留档倾向
- 黄色 `6-7`：可行，中优先级
- 绿色 `>=8`：强信号，优先处理

### 7.4 字体与排版

- 中文字体：系统栈（PingFang SC / Microsoft YaHei / Noto Sans SC）
- 数字/英文：等宽或同字族
- 字号层级：标题 14-16px / 正文 13px / 辅助 12px / 徽标 11px
- 行高：1.4-1.6；卡片内 4-6px 间距

### 7.5 圆角与阴影

- 卡片：8-10px 圆角，1px 边框（#e5e7eb）+ 极浅阴影
- 弹窗：12px 圆角 + 大阴影
- 徽标：全圆角（pill）

### 7.6 图标

- 线性图标（1.5px 描边），来源/标签/操作按钮可配图标
- 建议图标集：Lucide / Phosphor（开源，风格统一）

## 8. 现有界面问题清单（改进依据）

以下是当前实现的具体缺陷，设计时应逐一解决：

1. **灰屏遮挡 bug 已修**，但根源是弹窗样式设计脆弱——设计时明确弹窗 hidden/显示规范
2. 顶栏功能堆砌（5 按钮 + 2 下拉 + 1 开关），需要分组与图标化
3. 卡片信息密度低：摘要与徽标混排，无层级
4. 五列等宽布局：任务多时拥挤，无横向滚动提示
5. 无空状态、无加载骨架、无操作反馈（成功/失败全靠 alert）
6. 抽屉表单直排，无分区；评分明细裸 JSON 不可读
7. 无搜索、无批量操作（如批量删除留档）
8. 无数据可视化（评分分布/每日趋势/标签统计）
9. 移动端/窄屏无适配
10. 无深色模式
11. 拖拽无视觉反馈（落点、浮起）
12. "立即收集"按钮当前无实际功能（设计时预留接入位）

## 9. 设计交付建议

给设计师的落地提示：

1. **优先重设计首屏看板**（80% 使用时间都在看板 + 抽屉）
2. 产出物建议：浅色主题完整稿（桌面 1440px）+ 抽屉/弹窗组件稿 + 卡片三态（默认/悬停/拖拽）稿
3. 深色模式、移动端作为第二阶段
4. 组件规格（尺寸/色值/间距）与现有 HTML 结构对应，便于前端实现：现有结构为 `.col > .cards > .card`，抽屉 `#drawer`，弹窗 `#source-modal`/`#type-modal`
5. 交互规范（拖拽、确认、toast）需与实现成本平衡——原生 JS 无框架，避免过度复杂的动效依赖
