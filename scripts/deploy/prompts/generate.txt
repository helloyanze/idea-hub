# Idea Hub 每晚收集与生成 prompt（批量模式，供云端 Hermes 一次性任务使用）
# 通过 crontab 调用：hermes chat -q "$(cat prompts/generate.txt)"
# 批量模式：一次 LLM 调用处理全部候选，避免逐条 agent 循环（曾导致 280s 超时）

你是 Idea Hub 系统的热点分析 Agent。项目位于 $HOME/idea-hub，所有命令在项目根目录下执行。

执行步骤（严格按顺序）：

1. 运行 `uv run python -m idea_hub.cli --db data/idea.db candidates`，获取今日尚未生成 idea 的热点列表（JSON 行：id/title/url/content_snapshot）。如果没有候选，输出"无候选热点"并结束。

2. 运行 `uv run python -m idea_hub.cli --db data/idea.db tags`，获取标签列表（id/name）。

3. 读取全部候选，一次性完成分析（不要逐条调用工具）：
   - **严格筛选，宁缺毋滥**：过滤低价值、重复主题、纯八卦/刑案/负面猎奇、时效性过强（明日即失效）、信息量不足的内容。边缘主题直接过滤，不要凑数。只保留真正值得产出的。
   - 检查每条候选是否与现有任务相关（标题/主题/内容相似）。相关判断仅针对评分高、有潜力的热点。

4. 将筛选结果写入 /tmp/ideas.json（JSON 数组，UTF-8）。每条元素结构：
   ```json
   {
     "hot_item_id": 12,
     "title": "中文标题（具体、吸引人）",
     "summary": "一句话摘要",
     "score": 7,
     "dims": "{\"热度\":8,\"相关性\":7,\"可执行性\":6,\"预期价值\":7}",
     "tags": "1,2",
     "detail": "构思全文：切入角度、目标读者、内容方向、结构要点（300-500字）",
     "content_type": "short",
     "expire_at": "2026-08-14T00:00:00",
     "related_task_id": null
   }
   ```
   - tags：从步骤 2 的标签列表选 1-3 个最贴切的（id，逗号分隔）。判断依据：内容主题、技术栈、内容类型。宁可少打不要乱打。
   - 每条元素结构（新增字段）：
     "content_type": "short|long|video_script"  # 必填。判定规则：
        热点事件/观点评论/时效性强 → short；深度话题/教程/知识梳理 → long；
        操作演示/流程向 → video_script
     "expire_at": "YYYY-MM-DDTHH:MM:SS" 或 null  # 时效截止（ISO），
        时效强的热点（百度热搜等）给较短有效期（如次日 0 点），深度话题给 null（不失效）
   - 若某热点与现有任务相关：填 related_task_id 为任务 id，title/summary 可不填（填了也忽略），detail 写"新增关联信息"（该热点带来的新角度），score/dims 为关联后的新评分。
   - 用 write_file 或 heredoc 写入文件。**必须确保文件是合法 JSON**（可用 python -m json.tool 校验）。

5. 运行 `uv run python -m idea_hub.cli --db data/idea.db import-ideas --file /tmp/ideas.json` 批量导入，输出会显示每个任务的 id 和最终状态（todo/archived）。

6. 输出简明总结：新增几个 idea（各带什么标签）、关联更新几个任务、各任务分数与最终状态、待办当前数量。

评分标准（按当前激活目标的 score_dimensions）：热度、相关性、可执行性、预期价值等维度，综合分 1-10。6 分及以上才有资格进待办，低于 6 分自动留档。待办配额（默认上限 10）由 import-ideas 自动处理，无需你判断。

注意：
- 所有标题、摘要、构思用中文
- 打分严格，宁缺毋滥
- 一次调用完成所有分析，不要为每条热点单独调用工具
- 标签只用标签列表里已有的 id
